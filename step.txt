**План установки на Raspberry Pi**

1. Сначала проверить базу:

```bash
cat /etc/os-release
python3 --version
hostname -I
```

IP из `hostname -I` потом должен быть одинаковым в Android `baseUrl` и в Python `server_address`.

2. Поставить системные зависимости. Лучше не начинать с `pip`, а сначала закрыть системные пакеты:

```bash
sudo apt update
sudo apt install -y python3-full python3-venv python3-pip \
  python3-lgpio python3-rpi-lgpio python3-smbus i2c-tools \
  swig build-essential python3-dev
```

Если есть конфликт со старым `RPi.GPIO`:

```bash
sudo apt remove -y python3-rpi.gpio
```

3. Создать окружение правильно. В PDF легко ошибиться: нужен обычный двойной дефис `--`, а не длинное тире из текста.

```bash
cd ~
rm -rf lab4env
python3 -m venv --system-site-packages lab4env
source ~/lab4env/bin/activate
python -m pip install --upgrade pip
```

4. Внутри окружения удалить возможные полусломанные pip-версии GPIO-пакетов:

```bash
pip uninstall -y lgpio rpi-lgpio RPi.GPIO
```

Потом поставить только то, чего нет нормально через `apt`:

```bash
pip install smbus2 RPi.bme280 rpi_ws281x adafruit-circuitpython-neopixel
```

Если снова появится ошибка про `swig`, значит окружение всё ещё пытается собирать `lgpio` через pip. В этом случае надо проверить:

```bash
python -c "import lgpio; print('lgpio ok')"
python -c "import RPi.GPIO; print(RPi.GPIO.VERSION)"
```

Если эти импорты не работают, значит `venv` создан неправильно или не видит system-site-packages.

5. Включить I2C и проверить BME280/BMP280:

```bash
sudo raspi-config
```

Включить `Interface Options -> I2C`.

После перезагрузки:

```bash
i2cdetect -y 1
```

Нужно увидеть адрес `76` или `77`. В сервере сейчас стоит `0x76`:
[rpi_voice_home_server.py](/Users/all0b0y/Desktop/docs/ArduinoScripts/Лаб4_Голосовое_управление_умным_домом/Задание_3_стр104-106_RaspberryPi_server/rpi_voice_home_server.py:11)

Если датчик на `77`, поменять на:

```python
address = 0x77
```

6. Для WS2812B/NeoPixel на GPIO18 отключить аудио. Для новых Raspberry Pi OS путь обычно такой:

```bash
sudo nano /boot/firmware/config.txt
```

Найти или добавить:

```txt
dtparam=audio=off
```

Потом:

```bash
sudo reboot
```

Это важно, потому что LED-лента сидит на `board.D18`:
[rpi_voice_home_server.py](/Users/all0b0y/Desktop/docs/ArduinoScripts/Лаб4_Голосовое_управление_умным_домом/Задание_3_стр104-106_RaspberryPi_server/rpi_voice_home_server.py:19)

7. Запускать сервер лучше так:

```bash
sudo ~/lab4env/bin/python /home/USERNAME/rpi_voice_home_server.py
```

Или из папки с файлом:

```bash
sudo ~/lab4env/bin/python rpi_voice_home_server.py
```

Root нужен из-за NeoPixel. Важно: использовать именно Python из `lab4env`, а не просто `sudo python3`.

8. Исправить IP/порт в двух местах.

В Python лучше слушать все интерфейсы:

```python
server_address = ("0.0.0.0", 8000)
```

В Android должно быть:

```java
private static final String baseUrl = "http://IP_RASPBERRY:8000/";
```

Например:

```java
private static final String baseUrl = "http://192.168.1.100:8000/";
```

Сейчас порт в Android отсутствует, поэтому клиент будет стучаться на HTTP-порт `80`, а сервер работает на `8000`.

9. Проверить сервер без Android:

```bash
curl http://IP_RASPBERRY:8000/temperature
curl http://IP_RASPBERRY:8000/pressure
curl http://IP_RASPBERRY:8000/humidity
curl http://IP_RASPBERRY:8000/weather
curl http://IP_RASPBERRY:8000/FF0000
curl http://IP_RASPBERRY:8000/000000
```

Если `curl` работает, проблема уже не в Raspberry Pi-сервере, а в Android-сети/разрешениях/голосовом вводе.

10. Проверить Android:
- телефон и Raspberry Pi должны быть в одной сети;
- в `AndroidManifest.xml` уже есть `INTERNET`, `ACCESS_NETWORK_STATE`, `RECORD_AUDIO`, `usesCleartextTraffic=true`;
- приложение собрано успешно;
- голосовые команды должны быть на английском: `temperature`, `pressure`, `humidity`, `weather`, `turn on light color red`, `turn off light`.

Ключевой вывод: не надо хаотично ставить `rpi-lgpio` то через `apt`, то через `pip`. Для этой лабораторной самый стабильный путь: `apt` ставит `python3-lgpio` и `python3-rpi-lgpio`, окружение создаётся с `--system-site-packages`, а сервер запускается через `sudo ~/lab4env/bin/python ...`.
