## 0. Корневые находки (почему это делаем)

1. **Утечка `###`/`**`/`1.` в чат.** Не баг API и не баг модели. В
   `backend-go/internal/core/service.go` функция `sendRichRecipient` при невозможности
   отправить rich делает `fallback.ParseMode = ""` и шлёт **сырой markdown как plain text**.
   Те же грабли на ветке `RichFormattingEnabled=false` в `sendRecipient`. В `docs/backlog.md`
   это записано как «закрытый фикс» — на самом деле это и есть баг (фикс был неверный: «слать
   сырой plain» — именно то, что показывает пользователю `###`).
2. **Рассинхрон намерения и доставки.** Промпт (`ai-python/ai_agent/pipelines/draft.py`,
   `_compose_base_instruction`) **всегда** велит модели форматировать при назначенной роли,
   но доставка решает про rich на трёх независимых развилках (тумблер user/role/bot, ошибка
   `SendRichMessage`). Любая развилка сейчас роняет в сырой markdown.
3. **Модель ставит `###` в одну строку** с текстом/эмодзи (`😊 ### Заголовок`) — markdown
   требует пустую строку перед заголовком, иначе даже штатный rich парсится криво.
4. **Тиров моделей нет.** Привязка только по задаче (`MODEL_DRAFT`/`MODEL_CRITIC`/
   `MODEL_CHEAP`, `ai-python/ai_agent/agents/models.py`). Выбора «быстрый/основной/умный» и
   привязки тира к роли нет.
5. **Live-индикатор «мигает».** `richDraftFrames` (`service.go`) шлёт кадры
   thinking→половина→полный в плотном цикле без пауз — «печатается» мелькает и мгновенно
   заменяется готовым ответом.

**Что НЕ трогаем:** `speak_as_owner` (две рамки промпта, критик хранит границы) —
проверено, работает. Owner-only гейтинг бота пробовали и откатили — **не возвращать**.

## 1. Архитектурные решения (обязательные)

- **Деградация форматирования, а не дамп markdown.** Если rich отправить нельзя — markdown
  конвертируется в Telegram **HTML** (`parse_mode=HTML`), а если и HTML отклонён — markdown
  **вычищается** в читаемый plain. Сырой markdown в чат не уходит **никогда**.
- **Псевдо-стриминг готового безопасного текста** (как в phase2/phase3). Стримим только
  финальный текст после критика и `_scan_output`. Истинный токен-стрим из LLM — НЕ делаем
  (обходит safety, `CLAUDE.md`). Решение пользователя 2026-06-20: псевдо-стрим, **без показа
  размышлений** — только статус-индикатор «ответ готовится».
- **Тиры — конфигурация, не код.** Тир = env-список моделей (первый основной, остальные —
  `FallbackModel`). Роль выбирает тир. Отсутствие тира у роли → текущий путь
  `MODEL_DRAFT`/`OPENROUTER_MODEL` (обратная совместимость).

## 2. Реализация по фазам. Одна фаза за запуск. Тесты зелёные → СТОП.

### Фаза A — Починить утечку `###` (Go-only, приоритет 1)

1. Новый файл `backend-go/internal/telegram/mdrender.go`:
   - `MarkdownToHTML(md string) string` — конвертирует поддерживаемое Telegram-HTML
     подмножество: `**b**`/`__b__`→`<b>`, `*i*`/`_i_`→`<i>`, `~~s~~`→`<s>`, `` `code` ``→
     `<code>`, ` ```block``` `→`<pre>`, `[t](u)`→`<a href>`, `> цитата`→`<blockquote>`.
     Заголовки `#..######` → отдельная **жирная** строка. Списки `-/*/+`/`1.` → строки с
     `• `/`N. `. Таблицы — в plain-строки. Экранировать `& < >` в текстовых узлах.
   - `StripMarkdown(md string) string` — срезает разметку до чистого текста (заголовки без
     `#`, списки `• `, без `*`/`` ` ``), нормализует переводы строк.
2. В `sendRichRecipient` (`service.go`): rich-ошибка → отправить
   `MarkdownToHTML(text)` с `ParseMode="HTML"` через существующий `sendWithParseModeFallback`
   (он уже умеет ретрай в plain). Если HTML тоже отклонён — `StripMarkdown(text)` плоским
   текстом. Убрать ветку `fallback.ParseMode = ""` с сырым телом.
3. В `sendRecipient` ветка `!RichFormattingEnabled` (сейчас `return sendMessage(... raw)`):
   тоже слать `MarkdownToHTML`, а не сырой markdown.
4. Тесты (`telegram_test.go`, `service_test.go`): при ошибке rich-отправителя финальный
   `parse_mode` непустой ИЛИ тело очищено; **в теле нет `###`, `**`, `~~`**; HTML-падение →
   доставлен `StripMarkdown`; сообщение не теряется; идемпотентность отправки цела.
   **Обновить** тест из backlog, который сейчас ассертит пустой `parse_mode`.
5. `go test ./...` → СТОП + отчёт.

### Фаза B — Научить модель форматировать чисто (Python)

1. `ai-python/ai_agent/pipelines/draft.py`, `formatting_line` в `_compose_base_instruction`:
   ужесточить — markdown **только** для реально структурного ответа; заголовки/списки/таблицы
   **с пустой строкой до и после**; запрет `#`/`###` в одной строке с текстом или эмодзи;
   короткий ответ — обычный текст.
2. Добавить `normalize_rich_markdown(text: str) -> str` (pure-функция, module scope): вставляет
   `\n\n` перед `#{1,6}\s`, разделяет «эмодзи/текст + ###», чинит маркеры списков, схлопывает
   тройные переводы строк. Применять в `runtime.py` к `text` **только когда**
   `decide_text_format(...) == "rich"`, перед возвратом `DraftOutcome`.
3. Тесты (`tests/test_draft.py`): вход `"… 😊 ### Заголовок"` → заголовок с разрывом строки;
   `plain`-ответ не меняется; идемпотентность нормализации (двойной прогон стабилен).
4. `pytest` → СТОП + отчёт.

### Фаза C — Тиры моделей на роль через env (контракт-изменение)

1. **env** (`.env` + `docs`): три списка (первый — основной, дальше — фолбэки):
   ```
   MODEL_TIER_FAST="deepseek/deepseek-v4-flash,qwen/qwen3.6-flash,google/gemma-4-31b-it:free"
   MODEL_TIER_BALANCED="qwen/qwen3.7-plus,deepseek/deepseek-v4-pro"
   MODEL_TIER_SMART="deepseek/deepseek-v4-pro,qwen/qwen3.7-plus"
   ```

2. **Python** (`agents/models.py`): `class ModelTier(str, Enum) {FAST, BALANCED, SMART}`;
   `build_tier_model(tier) -> Model` — парсит список из env, строит `FallbackModel`-цепочку
   через ту же litellm/openrouter-логику (`openrouter/`-префикс как в `_build_litellm_model`).
   Пустой/нет env → деградация к `build_model(AgentTask.DRAFT)`.
3. **Runtime** (`agents/runtime.py`, draft-путь ~стр.510): пер-реквест override
   `self._draft_agent.run(user_payload, model=build_tier_model(role.model_tier), ...)` когда у
   роли задан тир; агент не пересоздавать. `model_used` отражает реальную модель тира.
4. **Контракт (обе стороны, frozen contract):** поле `model_tier`
   (`fast`|`balanced`|`smart`, default `balanced`) на `AIRoleData`:
   - `contracts/openapi.yaml` (схема роли);
   - `ai-python/ai_agent/schemas.py` (`AIRoleData` + `parse_ai_role`, дефолт при отсутствии);
   - `backend-go/internal/contracts/types.go` (поле роли);
   - `backend-go/internal/store/store.go` (чтение/запись `ai_roles`, `aiRoleColumns`).
5. **Миграция** `infra/migrations/111_role_model_tier.sql` (+`.down`): колонка
   `model_tier text` с CHECK на три значения, DEFAULT `'balanced'`. По образцу 106/107.
6. **UI** (`miniapp/screens/role-edit.js`): селект тира рядом с rich/streaming тумблерами;
   передавать `model_tier` в payload роли.
7. Тесты: роль с `model_tier=fast` резолвит первый из `MODEL_TIER_FAST`; пустой env →
   деградация к `MODEL_DRAFT`/`OPENROUTER_MODEL`; контракт round-trips (`test_contracts.py`,
   Go store-тест); миграция up/down + smoke-insert.
8. `pytest` + `go test ./...` → СТОП + отчёт.

### Фаза D — Live-индикатор «ответ готовится» (Go, поверх Фазы A)

1. **`sendChatAction: "typing"`** сразу при старте AI-хода авто-ответа (до готовности
   текста) — нативный сигнал «бот печатает…», работает на всех клиентах. Добавить метод
   `SendChatAction(ctx, chatID, action)` в `internal/telegram` если его нет.
2. Когда `StreamingEnabled` (эффективный) + `text_format=rich` + бот-транспорт
   (существующий гейт `richDraftStreamingAllowedFor`): поверх typing — **анимированный
   статус-индикатор** через `sendRichMessageDraft` (блок `<tg-thinking>` / нативные
   моргающие точки Bot API 10.1). **Только статус, без текста рассуждений.**
3. Переписать `richDraftFrames`: убрать кадр «половина ответа»; кадры = [индикатор] →
   (пейсинг готового безопасного текста чанками по предложениям/словам) → финал
   `sendRichMessage`. Добавить паузы между кадрами (небольшой `time.Sleep`/тикер,
   конфигурируемый), чтобы индикатор «дышал», а не мелькал.
4. Текст — ФИНАЛЬНЫЙ (после критика + `_scan_output`). Сырые частичные куски не слать.
5. Идемпотентность: индикатор/драфт-кадры не плодят постоянных сообщений; финал — один
   `sendRichMessage` по ключу отправки. Падение драфт-кадра → финал всё равно уходит (фолбэк
   Фазы A). Бизнес-транспорт и review-путь — без стриминга (стримить некуда).
6. Тесты: стрим-путь только при ВКЛ тумблере и rich; первый кадр — статус, не ответ; финал
   доставлен даже при падении драфт-кадра; при ВЫКЛ — путь Фазы A без регрессий.
7. `go test ./...` → СТОП + отчёт.

## 3. Безопасность и инварианты (CLAUDE.md)

- Стрим/деградация отдают только финальный текст после `OutputSafetyScanner`/`deanonymize` —
  никаких сырых частичных кусков.
- Privacy-флаги (`no_memory`/`no_training`/`no_summary`/`private`) логику не меняют.
- Идемпотентность отправки/одобрения сохраняется.
- `speak_as_owner` не трогать; owner-only гейтинг не возрождать.
- Go: `slog`, без `fmt.Println`; ошибки обработаны или `_` с комментарием. Python:
  type-аннотации, `frozen=True`, без bare `except`. Найденные неэффективности/долги — в
  `docs/backlog.md`.

## 4. Критерии приёмки

1. Ни при каком фолбэке собеседник не видит сырой markdown (`###`, `**`, `~~`, `1.`).
2. Заголовки/списки от модели идут с корректными разрывами строк; rich парсится без артефактов.
3. Роль выбирает тир (fast/balanced/smart); тир резолвит список моделей из env с фолбэк-цепью;
   отсутствие тира → текущее поведение без регрессий.
4. При ВКЛ потоковом режиме собеседник видит индикатор «печатается/Thinking», затем готовый
   отформатированный ответ; отправляется только безопасный финальный текст.
5. Контракт синхронизирован (openapi + Python + Go); старые роли без `model_tier` работают.
6. Все тесты зелёные.
